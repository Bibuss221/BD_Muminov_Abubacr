# Связь приложений пояснительной записки с GitHub

В пояснительной записке Муминова приложения разделены по смыслу.

| Приложение ПЗ | Что там находится | Где это лежит в репозитории |
| --- | --- | --- |
| Приложение А | Примеры SQL-команд создания структуры базы данных | `database/schema.sql` |
| Приложение Б | Триггерные функции и серверная бизнес-логика | `database/triggers.sql` |
| Приложение В | Роли и права доступа | `database/roles.sql` |

Дополнительный код, который в тексте ПЗ описан отдельными подразделами:

- представление `v_car_rent_summary` → `database/views.sql`;
- функция расчёта стоимости → `database/functions.sql`;
- индексы → `database/indexes.sql`;
- проверка оптимизации → `database/optimization.sql`;
- резервное копирование → `scripts/backup_database.ps1`;
- восстановление → `scripts/restore_database.ps1`;
- тестирование бизнес-правил → `tests/database_business_rules.sql`.

Так структура репозитория не скрывает происхождение SQL: основа серверной части совпадает с приложениями ПЗ, а C++/Qt слой является клиентской реализацией.


## Объём демонстрационных данных

Заполнение выполняется SQL-генерацией через `generate_series()`, поэтому в репозитории не хранится несколько тысяч вручную перечисленных INSERT-строк. После запуска `database/seed.sql` получается не менее 500 записей в каждом отношении: 500 клиентов, 500 автомобилей, 500 скидок, 750 сделок, 500 штрафов и 750 применений скидок.
